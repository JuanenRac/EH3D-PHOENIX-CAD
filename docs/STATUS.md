# EH3D-PHOENIX-CAD: status

## Current state

EH3D-PHOENIX-CAD is early code. Beside the base that every repository of the suite carries (manifest, README files in eight languages, changelog, CI, shared checks) and the written scope, requirements, dependencies, threat model and decisions, it has a Rust library, `eh3d-phoenix-cad`: lengths in integer nanometres with their own range, a parametric enclosure with round, countersunk, counterbored, rectangular and oval holes in its faces and rounded or chamfered edges, structured change operations that report conflicts and leave the model unchanged (each with an exact inverse), an OpenSCAD-style script, and a fit check of the envelope of a board. It has only been tried on models made by its own tests. It also writes the enclosure as a STEP file (a boundary representation with the inner space as a void and a cylindrical face for each hole), the same text for the same model; that file has only been checked for its structure (header, references, counts) and no CAD program has opened it, and it draws only the box with straight round holes: a model with rounded or chamfered edges or another kind of hole is refused by `export_step`, while the script draws them all. Around it the library has integer angles with an integer sine and cosine, units of length read and shown in mm, um, in and mil, stable names for faces, edges and hole walls, a recipe of steps with a tip, suppressed steps and an undo history, a settings file with a printer profile, a table of screws and a table of densities, atomic saving with numbered copies, the volume, the mass, the centre of mass and the moments of inertia, patterns of holes, a graph of dependencies with a recalculation that only does what changed, named variables and variants, parameters that are values, variables or expressions (a small language with units, functions and conditions over exact fractions, whose limits are in the settings) calculated through the graph of dependencies, reference frames, the envelope of a project file, and the text of every diagnostic in eight languages. The box also has posts that rise from the floor under the mounting holes of a board (a bore for a threaded insert or a self-tapping screw taken from the table of the settings, an optional conical foot, checks against the walls, the other posts, the holes of the floor and the height of the board and its tallest part) and a lid that is screwed into them (a through hole with a recess for the head over each post, or over the four corners when there are no posts, and an optional centring lip with the clearance of the printer profile); the script draws all of it and the STEP file draws the posts with a plain bore. The project file keeps the recipe of the box in its mechanical domain (the parameters, the ordered steps, the tip and the interface of the board), read again to the same box, with a migration from the older domain of the parameters; the contract is in `docs/PROJECT_DOMAIN.md`. There is no command line, no server task, no heat sink, no sketch and no assembly, and nothing has been run on a machine.

## The window

The program has a window (egui, built with `--features gui`): a tree of the model, a panel of properties where a dimension (a length, a variable or a formula) or the value of a hole, a post, an edge treatment or the lid is edited and the box is built again, a 3D view and a plan drawn as lines, undo and redo, a sheet of variables (a value or a formula for each, what it calculates to and the parameters that use it) and buttons that add a hole, a post or the edge treatment and remove a step, and a status bar with the sizes, the fit of the board and the steps the model refused. The state of the window, the edits, the history, the views and the texts in the eight languages are code of the library that is tested without a screen. The drawing code of the window itself has been written against the interface of the library and has never been opened on a screen: its look, its layout and its behaviour with the mouse are not checked by any test. The `check` command reads a project and prints the same measures and the state of every step.

## Capabilities

The official state of each capability is in REQUIREMENTS.md: 6 requirements: 4 `prototype` (FCAD-001, FCAD-003, FCAD-004, FCAD-006) and 2 `planned`. This page never states a state that REQUIREMENTS.md does not.

## Open questions

* Which geometry kernel and constraint solver to use. Candidates being looked at: a Rust solid-modelling crate with STEP support, OpenCASCADE through bindings (not verified), the SolveSpace solver through the slvs crate (GPL-3.0) and planegcs (LGPL, not verified). Licences must be compatible with GPL-3.0-or-later.
* Where the 3D board view and the enclosure fit check live: here or in the board tool.

## Known technical debt and omitted tests

The holes and the posts carry the shared object identity (UUID v7 of EH3D-COMMON). The mechanical domain of the project format is written and read by this repository only: the board tool does not read the interface of the board or write steps yet, and no real project has gone through it. The posts and the lid have been tried on boxes and boards made by their own tests; nothing has been printed, and the bores of the table of posts were typed by hand and are not compared with any insert or screw. The script with posts and lid has not been opened in OpenSCAD, and the STEP file with posts has been checked for its structure only. The mass and the moments leave the posts, the lip and the holes of the lid out and say so. The language of expressions has only been tried against hand-made tables and generated expressions, never inside a design; its sine and cosine come from the integer table of angles (nine decimals), and it has no tangent, no area or volume, and no functions defined by the person. The script has not been opened in OpenSCAD and nothing is compared with a reference CAD program. The table of screws and the table of densities in the settings file were typed by hand and are not compared with any standard. The volume of a hole is exact only when the hole lies in the thin part of its face; otherwise the figure says it is not. The centre of mass and the moments of inertia are checked against an independent calculation of the same sums, not against a CAD program, and they say when a countersink, a slot or the treatment of the edges was approximated or left out. Saving has been tried on the file system of the machine that runs the tests only.
