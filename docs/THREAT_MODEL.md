# EH3D-PHOENIX-CAD: threat model

Basic model for early code. Each row says what the code does about the threat today and how that was tried; nothing has been run on a machine and nothing here has been fuzzed.

| Threat | Mitigation | Test | State | Residual risk |
|---|---|---|---|---|
| Hostile or malformed STEP or 3D model from a third party | the program reads no STEP file and no 3D model: it only writes a STEP file; a reader, when there is one, needs bounded parsers, size and depth limits, and a provenance and licence record | none: there is no reader | not applicable yet | a reader added later needs its own hostile samples |
| Corrupt or malicious project, sketch or settings files (oversized entries, deep nesting, resource exhaustion) | every file is read under a size limit (`store::load_limited`, `max_bytes`, `max_file_bytes`); the texts are in one canonical form and anything else is refused with a code; the number of domains, steps, names, elements, constraints and sketches is limited by settings; a domain that is not understood, of a newer version or damaged is kept byte for byte and the project is opened read-only; the messages never copy a name or a value from the file | the tests cut every good domain at every byte, refuse the non-canonical spellings, the limits on both sides and the damaged and newer-version domains, and write a project again to get the same bytes | implemented, tried with hand-made cases | no fuzzing; a file just under the limits can still take long to solve (the solver of a sketch is bounded by its steps and not by a clock) |
| Temporary files, logs and reports that reveal private designs | the library writes no log and no report; the commands print measures and states only; the temporary file of a save sits next to the target and is removed | none beyond the saving tests | implemented in part | not assessed: a person can still send a project file to somebody else |
| Compromised dependency or binary | one dependency of the suite, checked out at the tag named in the CI, and the window libraries with their versions locked in `Cargo.lock`; no advisory check, no licence check and no bill of materials yet | the CI builds and tests on Linux and Windows | partly: locked, not audited | not assessed |
| Power loss or forced close during a save | atomic write: temporary file, flush, then rename; the older files are kept as numbered copies | the tests save, replace and keep copies on the file system of the machine that runs them | implemented, tried on one file system | no test interrupts a save at a controlled point |

Minimum negative tests: hostile files and resource limits (done for the project, the sketch and the settings with hand-made cases, not fuzzed); secrets absent from logs, errors and reports (the code has none to leak); pinned dependencies and licence review before publishing (not done). Report a vulnerability privately as described in SECURITY.md, without attaching private designs.
