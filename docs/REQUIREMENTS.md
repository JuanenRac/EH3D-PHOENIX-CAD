# EH3D-PHOENIX-CAD: requirements

This register is the single source of the state of each capability. Status values: planned, prototype, implemented, validated. Four requirements (FCAD-001, FCAD-003, FCAD-004 and FCAD-006) are `prototype` and the other two are `planned`: none is validated and nothing has run on a machine. High test coverage is not proof of geometric or electrical correctness, so each requirement says how it will be checked and what result is expected.

| Requirement | Description | Status | How it will be checked | Expected result | Known limits |
|---|---|---|---|---|---|
| FCAD-001 | Generate a simple parametric enclosure from named parameters. | prototype | automatic: dimensional reference cases | A regenerated model with the same parameters is identical. | Only the box with round holes in its faces exists, in `eh3d-phoenix-cad`; no rounded corners, no ribs, no standoffs, no vents, no lid fixing. Checked with hand-made reference cases only. |
| FCAD-002 | Export the model to STEP. | planned | automatic: re-read the export and compare dimensions | Exported solids keep their dimensions within a stated tolerance. | Still `planned`: `eh3d_phoenix_cad::step::to_step` writes the enclosure as an AP214-style boundary representation (outer box, inner space as a void, a cylindrical face for each hole), identical for the same model; the tests check the header, that every reference points to an earlier entity and the counts of faces, edges and cylinders, but no program has re-read the file to compare dimensions, so it is not yet `prototype`. |
| FCAD-003 | Export the model as an OpenSCAD-style script. | prototype | automatic: golden files | Same parameters give the same script. | The script of the box and its holes is written as plain text in millimetres, the same text for the same model whatever the order of the operations; it has not been opened in OpenSCAD yet, and the placement of the holes on every face is checked against the text only. |
| FCAD-004 | Apply structured change operations coming from the board tool and report conflicts. | prototype | automatic: operation tests, including conflicting ones | A rejected operation leaves the model unchanged. | Operations on holes and on the parameters exist, each with an exact inverse, and a refused one leaves the model equal to what it was; the operations do not come from the board tool yet because the mechanical domain of the project format is not written. |
| FCAD-005 | Heat-sink model with declared dissipation assumptions for the thermal lab. | planned | automatic plus review | Every assumption is stored with the model. | Not started: no limits known yet. |
| FCAD-006 | Mechanical coordinates follow their own range rule, not capped by the board limit. | prototype | automatic: property tests | A chassis larger than a board is representable. | Lengths in integer nanometres below 2^40 (about 1100 m) against 2^30 for the board; checked with unit tests, not with property tests. |

Rules: a claim of correctness names the corpus, the tolerance and the tool version it holds for. A phase is complete when the measured rate does not drop, every failure is classified and fixed or documented, and the measured figure is reported.
